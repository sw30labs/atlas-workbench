# ADR-012: Runtime artifacts gitignored and regenerated

- **Status:** accepted
- **Date:** 2026-08-01

## Context

Files like `emerging_risks.json`, `compound_scenarios.json`, `atlas.db`,
and `generated/` outputs change on every pipeline run. Meanwhile tests
must not depend on frozen runtime content.

## Decision

Runtime artifacts are gitignored and regenerated by pipeline runs;
nothing in version control depends on their contents. Tests that touch
them assert **structure, not frozen values** (e.g., risk count is read
from the file, not hardcoded). Binary databases are never committed;
schema migrations bootstrap them on first run.

## Consequences

- The repo stays a code+spec repository; data is local.
- **Narrowed by [ADR-015](015-human-decision-durability.md):** "re-run the
  pipeline" is not a recovery story for `emerging_risks.json`, which holds
  human review decisions that no re-run reproduces. Those are protected by a
  pre-write snapshot and a separate data history instead. This repository's
  contents are unchanged — runtime artifacts stay gitignored here.
- Tests pass regardless of what a live pipeline did to the catalog
  minutes earlier (learned the hard way when a live run added three
  risks mid-session).
- Recovery story is "re-run the pipeline," not "restore from git."

## Alternatives considered

- **Commit demo snapshots** — partially done via `examples/` fixtures
  (curated, synthetic); live outputs stay uncommitted.
